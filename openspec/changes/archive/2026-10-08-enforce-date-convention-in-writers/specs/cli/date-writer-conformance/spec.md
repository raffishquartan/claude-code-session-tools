## ADDED Requirements

### Requirement: Every date format CCST writes is a convention form or a listed exemption
Every date or time that CCST code writes into a file, a database field, a frontmatter block or
printed output SHALL be one of these forms:
- `yyyy-MM-dd`, `yyyy-MM`, `yyyy`, `yyyy-MM-dd HH:mm` (optionally followed by `UTC`), or a range
  `a..b` of two such values;
- machine ISO 8601 with `T` and `Z` or an offset, where the value is stored, compared, parsed
  back or exchanged with an external system;
- `yyyy.MM.dd`, `yyyy.MM.dd-HHmm` or `yyyy.MM` in the date part of a file or folder name;
- a form on the exemption list: an identifier that contains a date (session tag, branch name), a
  backup or snapshot stamp, a name generated by a tool CCST does not control, or a time of day
  with no date.
The exemption list SHALL name each exempt format string with its reason, and a format string not
on the list SHALL NOT appear in `src/`.

#### Scenario: A new strftime format is added
- **WHEN** a change adds `strftime("%d/%m/%Y")` anywhere under `src/`
- **THEN** the conformance test fails and names the file, the line and the format string

#### Scenario: An exempt stamp keeps its form
- **WHEN** CCST writes a backup file name with a compact stamp such as `%Y%m%d-%H%M%S`
- **THEN** that form is on the exemption list with the reason "backup stamp" and the test passes

#### Scenario: A stale exemption is removed
- **WHEN** an exemption-list entry no longer matches any format string in `src/`
- **THEN** the conformance test fails until the entry is deleted
